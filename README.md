# KyivAir

Веб-застосунок, який показує якість повітря (AQI) у 10 районах Києва: інтерактивна карта, поради простою мовою, історія вимірювань за 24 години та 7 днів.

Дані — з відкритої мережі датчиків [Sensor.Community](https://sensor.community). Бекенд опитує датчики кожні 10 хвилин, прив'язує їх до районів за координатами і рахує AQI за шкалою US EPA.

Командний проєкт, КНУ імені Тараса Шевченка, 2026.

## Як це працює

```
Sensor.Community API ──► collector ──► SQLite ──► REST API (FastAPI) ──► фронтенд (карта, графіки)
   (PM2.5, PM10                │                         /api/...              /
    з датчиків)          район за координатами,
                         медіана по датчиках, AQI
```

1. **Збір даних** (`backend/app/collector.py`). Раз на 10 хв завантажуються останні вимірювання всіх датчиків у радіусі 25 км від центру Києва. Записи без PM, з неправдоподібними значеннями чи битою датою відкидаються.
2. **Прив'язка до районів** (`backend/app/districts.py`). Для кожного нового датчика район визначається алгоритмом «точка в многокутнику». Датчики за межами міста ігноруються.
3. **Розрахунок AQI** (`backend/app/aqi.py`, `aggregate.py`):
   - для кожного датчика рахується середнє за годину;
   - для району береться медіана по його датчиках, тому один збійний датчик не псує результат;
   - AQI району — більше з двох значень: AQI за PM2.5 і AQI за PM10 (шкала US EPA 2024).
4. **REST API** (`backend/app/main.py`) віддає поточний стан і погодинну історію районів, а також роздає фронтенд.
5. **Фронтенд** (`frontend/`): чистий HTML/CSS/JS і Chart.js, без збирання.

## Структура

```
backend/
  app/
    main.py              REST API + роздача фронтенду
    collector.py         збір даних за розкладом
    sources/             джерела даних (Sensor.Community; можна додати інші)
    aggregate.py         агрегування по районах і годинах
    aqi.py               формула AQI
    districts.py         райони, точка в многокутнику
    db.py                схема SQLite
    demo.py              демо-дані для показу без інтернету
  tests/                 pytest
frontend/
  index.html, css/, js/  інтерфейс
  tests/                 модульні (node:test) та браузерні (Playwright) тести
shared/districts.geojson межі районів (спільні для бекенду й фронтенду)
Dockerfile               контейнер для хостингу
```

## Запуск локально

Потрібні Python 3.11+ (для тестів фронтенду ще Node.js 20+).

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

Відкрийте http://localhost:8000: перший збір даних запускається одразу при старті. Документація API — на http://localhost:8000/docs.

Немає інтернету або треба показати проєкт без живих даних — заповніть базу демо-даними за 7 днів:

```bash
python -m app.demo           # додати демо-датчики (id починаються з demo:)
python -m app.demo --clear   # прибрати їх
```

Інші команди:

```bash
python -m app.collector                  # один цикл збору даних вручну
KYIVAIR_COLLECT=0 uvicorn app.main:app   # запуск без фонового збору
```

## REST API

| Метод | Шлях | Що повертає |
|---|---|---|
| GET | `/api/districts` | список районів (`id`, `name`) |
| GET | `/api/districts/current` | поточний AQI усіх 10 районів (за останню годину) |
| GET | `/api/districts/{id}/history?from=&to=` | погодинна історія, за замовчуванням 24 год, максимум 31 день |
| GET | `/api/health` | стан сервісу: кількість датчиків, результат останнього збору |

Приклад відповіді `/api/districts/current`:

```json
[{ "id": "pecherskyi", "aqi": 74, "pm25": 23.1, "pm10": 37.4,
   "dominantPollutant": "pm25", "sensorsCount": 3, "updatedAt": "2026-11-10T17:10:52Z" }]
```

Якщо в районі немає свіжих даних, повертається `"aqi": null`, і на карті район показується як «Немає даних». Години без вимірювань в історії теж мають `aqi: null`.

## Тести

```bash
cd backend && pytest -q                              # 49 тестів: AQI, райони, збір, API

cd frontend
npm ci
npx playwright install chromium                      # один раз
npm test                                             # модульні тести інтерфейсу
npm run test:e2e                                     # 13 браузерних сценаріїв
```

GitHub Actions запускає всі тести на кожен push (`.github/workflows/tests.yml`).

Фронтенд можна запустити й без бекенду, на згенерованих у браузері даних: додайте `?mock=1` до адреси. На GitHub Pages цей режим вмикається автоматично. Тестові сценарії: `?mock=1&scenario=offline`, `error`, `stale`, `hazard`.

## Деплой

Застосунок — один контейнер (`Dockerfile`), його можна розгорнути на Render, Railway, Fly.io тощо.

На Render: **New → Web Service → репозиторій → Runtime: Docker**. Порт визначається автоматично зі змінної `PORT`.

На безкоштовних тарифах диск не постійний, тому після перезапуску історія накопичується заново.

## Обмеження

- **Межі районів на карті схематичні.** Щоб показати реальні, замініть `shared/districts.geojson` (наприклад, межами з OpenStreetMap) і координати в `frontend/js/districts.js`. Тест `test_ids_match_frontend` перевіряє, що id районів збігаються.
- **Дешеві датчики (SDS011) завищують PM за високої вологості.** Корекції на вологість поки немає.
- **AQI рахується як середнє за останню годину**, а не за алгоритмом NowCast, який використовує EPA.
- **Тексти порад** — це загальні рекомендації, а не медичні поради.
